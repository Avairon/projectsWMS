### Проект: Веб-система «Реестр проектов НХТК»

---

## КОНТЕКСТ ПРОЕКТА

Вы — эксперт по написанию дипломных работ в области разработки программного обеспечения и анализа рынка IT-продуктов. Ваша задача — сгенерировать третью главу дипломного проекта объёмом 8-12 страниц текста (без учёта схем и таблиц) на основе предоставленной информации о реализованной системе.

### Описание системы

Разработана веб-система «Реестр проектов НХТК» для автоматизации управления проектами в образовательной организации (колледже). Система предназначена для координации работы над учебными и производственными проектами, контроля выполнения задач и формирования отчётности.

**Технологический стек:**
- Backend: Python 3.12+, Flask (веб-фреймворк)
- Frontend: HTML5, CSS3, JavaScript, Bootstrap 5, Flatpickr (календарь)
- База данных: JSON-файлы (users.json, projects.json, tasks.json, tokens.json, directions.json)
- Дополнительные библиотеки: Flask-Login, openpyxl (экспорт Excel), python-dateutil

**Архитектура системы:**
```
/workspace/
├── app/
│   ├── __init__.py          # Фабрика приложения Flask
│   ├── models.py            # Модель пользователя (UserMixin)
│   ├── tables.py            # Класс DataTable для фильтрации данных
│   ├── utils.py             # Утилиты (БД, токены, файлы, история)
│   ├── routes/
│   │   ├── auth.py          # Аутентификация и регистрация
│   │   ├── dashboard.py     # Главная панель и статистика
│   │   ├── projects.py      # CRUD проектов
│   │   ├── tasks.py         # CRUD задач и подзадач
│   │   └── reports.py       # Отчёты с фильтрацией и Excel
│   ├── templates/           # HTML-шаблоны (14 файлов)
│   └── static/              # Статические файлы
├── database/                # JSON-хранилище данных
├── uploads/                 # Загруженные файлы отчётов
├── config.py                # Конфигурация
└── run.py                   # Точка входа
```

**Ролевая модель:**
1. **Администратор** — полный доступ, управление пользователями, направлениями, генерация токенов
2. **Руководитель проекта (manager)** — создание проектов, назначение кураторов и исполнителей
3. **Куратор (supervisor)** — контроль выполнения задач проекта
4. **Исполнитель (worker)** — выполнение задач, загрузка отчётов

**Ключевой функционал:**
- Регистрация пользователей по токенам (система одноразовых токенов)
- CRUD операций для проектов, задач, подзадач
- Иерархия: Проект → Задачи → Подзадачи с дедлайнами
- Загрузка файлов отчётов (png, jpg, pdf, doc, xlsx и др.)
- История изменений задач (аудит действий пользователей)
- Фильтрация и поиск по таблицам (текстовый поиск, диапазон дат)
- Экспорт отчётов в Excel с форматированием
- Разграничение доступа на основе ролей и принадлежности к проектам

**Текущие метрики системы (на момент анализа):**
- Количество проектов: 7 (6 в работе, 1 приостановлен)
- Количество задач: 7 (6 активных, 1 завершена)
- Количество пользователей: 7 (2 администратора, 2 менеджера, 1 куратор, 2 исполнителя)
- Направления проектов: Цифровая среда, Образовательные программы, Профессионалитет, Промталанты, Работодатели

#### 3.2.1. Этапы жизненного цикла разработки
Опишите пройденные этапы жизненного цикла продукта по модели SDLC:

1. **Инициация (Initiation)**

3. **Проектирование (Design)**

   - Проектирование базы данных (ER-модель)

4. **Разработка (Implementation)**

#### 3.2.2. Модель жизненного цикла продукта на рынке
Опишите текущую стадию продукта на рынке по модели PLC (Product Life Cycle):

1. **Внедрение (Introduction)** — текущая стадия
   - Характеристика: ранние пользователи, низкие продажи, высокие затраты
   - Стратегия: информирование рынка, обучение пользователей
   - Метрики: количество активных пользователей, обратная связь

2. **Рост (Growth)** — планируемая стадия
   - Характеристика: рост adoption, положительная динамика
   - Стратегия: масштабирование, добавление функций
   - План действий: расширение на другие образовательные учреждения

3. **Зрелость (Maturity)** — перспективная стадия
   - Характеристика: насыщение рынка, стабильные доходы
   - Стратегия: дифференциация, оптимизация затрат
   - План действий: разработка premium-функций, партнёрства

4. **Спад (Decline)** — риски и меры предотвращения
   - Факторы риска: появление конкурентов, изменение требований
   - Меры: постоянное обновление, мониторинг рынка

### **3.4. Оценка экономической эффективности** (~1-2 страницы)

#### 3.4.1. Расходы на разработку
Рассчитайте затраты на создание системы:

**Трудовые затраты:**
- Разработка backend: ~120 часов
- Разработка frontend: ~80 часов
- Проектирование и тестирование: ~60 часов
- Итого: ~260 часов

**Стоимость разработки:**
- При ставке разработчика 1500 руб/час: 260 × 1500 = 390 000 руб.
- Стоимость инфраструктуры (сервер, домен): ~10 000 руб/год
- Общие затраты первого года: ~400 000 руб.

#### 3.4.2. Экономия от внедрения
Опишите экономический эффект:

**Прямая экономия:**
- Отсутствие лицензионных платежей (аналоги: 500-2000 руб/пользователь/месяц)
- При 50 пользователях: 50 × 1000 × 12 = 600 000 руб/год экономии

**Косвенная экономия:**
- Сокращение времени на подготовку отчётности: ~4 часа/неделю × 52 недели × 1500 руб = 312 000 руб/год
- Уменьшение количества просроченных проектов: оценка 100 000 руб/год
- Итого косвенная экономия: ~412 000 руб/год

**ROI (Return on Investment):**
- Год 1: (600 000 + 412 000 - 400 000) / 400 000 × 100% = 153%
- Год 2: (600 000 + 412 000 - 10 000) / 10 000 × 100% = 10 020%

#### 3.4.3. TCO (Total Cost of Ownership) на 3 года
- Год 1: 400 000 руб (разработка + инфраструктура)
- Год 2: 10 000 руб (инфраструктура + поддержка)
- Год 3: 10 000 руб (инфраструктура + поддержка)
- Итого TCO: 420 000 руб за 3 года

**Сравнение с аналогами:**
- Bitrix24 (50 пользователей): 50 × 1200 × 12 × 3 = 2 160 000 руб
- Экономия: 2 160 000 - 420 000 = 1 740 000 руб (81%)
